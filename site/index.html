One command. Two cuts.

PreToolUse rewrites the invocation to prunesh <cmd>. The proxy runs the real tool, then prunes stdout before it reaches the agent. Hooks are inert without a .prunesh marker at the project root.

Everything is a module

The core is a hook, a proxy, and a registry. Modules never import each other. Built-in and marketplace plugins implement the same registry.Module interface — the proxy cannot tell them apart.

Built-in

Compiled into the binary via blank imports in main.go. Not installed to disk. Ships with git, ls, find, grep, rg, tree, docker, cargo, go, npm, pytest, python, and Read/MCP filters.

Marketplace

External binaries installed to ~/.prunesh/plugins/ and registered in plugins.db. Contract stdin/v1: JSON on stdin/stdout. Any language. Core stays closed.

What ships in the binary

Built-in modules compile into prunesh. Marketplace plugins extend the same registry without touching core.

Publish your own plugin

No pull request. No shared tokens. A GitHub release with a valid stdin/v1 binary registers the plugin automatically.

01 · Contract

Ship stdin/v1

Implement rewrite and filter_output over JSON stdin/stdout. Release must include prunesh.json and binaries named <command>-<os>-<arch>.

02 · Workflow

Copy the template

Add templates/publish.yml to your plugin repo. Set plugin_id to author/command.

03 · Release

Tag and publish

Create a GitHub release (v1.0.0). OIDC authenticates the worker. If the contract probe passes, the plugin is live within minutes.
